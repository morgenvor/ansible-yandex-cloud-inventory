# Отличия форка от upstream

Форк [morgenvor/ansible-yandex-cloud-inventory](https://github.com/morgenvor/ansible-yandex-cloud-inventory)
основан на [mzatolokin/ansible-yandex-cloud-inventory](https://github.com/mzatolokin/ansible-yandex-cloud-inventory)
(ветка `main`, коммит `d2ad1ab`, автор Maksim Zatolokin, лицензия MIT).
Upstream-автор неактивен около года, поэтому исправления выпускаются из форка.

Этот документ — публичный список отличий: что было в upstream, что стало здесь и
что нужно поменять при переходе. Версия форка — `2.0.0`.

## 1. Исправления поведения (появились в 1.0.1)

| # | Было в upstream | Стало в форке |
|---|---|---|
| 1 | `ansible_host` брался из внутреннего IP | `ansible_host` — публичный IP, если он есть; внутренний остаётся в `private_ipv4` |
| 2 | `verify_file` принимал любой `*.yml`/`*.yaml`, чужой inventory ломался с «Incorrect plugin name» | принимаются только `yc_inventory.yml`/`yc_inventory.yaml` и `*_yc_inventory.yml`/`*_yc_inventory.yaml` |
| 3 | читалась только первая страница `ListInstances` (100 ВМ), остальные терялись | постраничный обход по `next_page_token`, `page_size=1000` |
| 4 | ВМ без сетевых интерфейсов роняла плагин с `IndexError`, Ansible отдавал пустой inventory | ВМ пропускается с предупреждением, остальные хосты на месте |
| 5 | дефисы заменялись на `_` и в ключах, и в значениях меток (`web-app` → `web_app`) | значение не меняется, нормализуется только ключ |
| 6 | имя ВМ писалось в переменную `name` — Ansible ругался «Found variable using reserved name» | переменная называется `yc_name` |
| 7 | `ansible: false` сравнивалось с учётом регистра | сравнение без учёта регистра (`False`, `FALSE` тоже работают) |

## 2. Изменения контракта меток (2.0.0)

Метки ВМ — недоверенный ввод: поставить их может любой, у кого есть доступ к
каталогу. До 2.0 метка попадала в переменные хоста «как есть», то есть метка
`ansible_host` подменяла адрес подключения, а `ansible_ssh_common_args` с
`ProxyCommand` выполняла произвольную команду на контроллере.

В 2.0 метки больше не могут переопределить служебные переменные:

| Что | Было (1.x) | Стало (2.0) |
|---|---|---|
| метка `role: web-app` | переменная `role = web-app` | `yc_label_role = web-app` |
| метка `owner-team` | переменная `owner_team` | `yc_label_owner_team` |
| метка `ansible_host: 203.0.113.99` | подменяла адрес подключения | `yc_label_ansible_host`, `ansible_host` = реальный IP, предупреждение |
| метка `ansible_ssh_common_args` | становилась переменной хоста | только `yc_label_ansible_ssh_common_args`, предупреждение |
| метка `ansible_user` | применялась | применяется (белый список) и дублируется как `yc_label_ansible_user` |
| метка `ansible_port` | применялась | применяется (белый список) и дублируется как `yc_label_ansible_port` |
| метка `ansible_group` | директива группировки | без изменений (директива) |
| метка `ansible: false` | фильтр | без изменений (фильтр) |

Белый список — `ansible_user` и `ansible_port`: без них плагин терял бы
возможность управлять учётной записью подключения, а эти две переменные не
выполняют код на контроллере. Остальные `ansible_*`-метки остаются доступны как
`yc_label_*` и сопровождаются предупреждением с именем ВМ и ключом.

## 3. Надёжность (2.0.0)

| Ситуация | Было | Стало |
|---|---|---|
| у ВМ нет `primary_v4_address` | `AttributeError`, inventory пустой | предупреждение, ВМ пропущена, остальные хосты на месте |
| у первого интерфейса нет IPv4-адреса (в API это пустое сообщение с `address == ""`, а не `None`) | `AttributeError` и пустой inventory; после первой версии фикса — хост с `ansible_host: ""` | предупреждение, ВМ пропущена |
| две ВМ дают одно имя хоста (`web-1` и `web_1`) | одна ВМ молча исчезала | предупреждение с обоими именами, остаётся последняя — вместе со своей зоной |
| два ключа меток после нормализации совпали (`a-b` и `a_b`) | одна переменная молча затирала другую | предупреждение, в переменной остаётся последняя |
| `myyc_inventory.yml` | перехватывался плагином | обслуживается штатным yaml-плагином (нужен разделитель `_`) |

## 4. Упаковка (2.0.0)

- `requires-python = ">=3.11"`: `ansible-core>=2.18.6` требует Python 3.11+,
  заявленные ранее 3.8–3.10 установить всё равно было нельзя.
- Лицензия описана по PEP 639 (`license = "MIT"`, `license-files = ["LICENSE"]`),
  дублирующий classifier `License :: OSI Approved :: MIT License` убран.
- В sdist входят `tests/`, `examples/`, `docs/` — по архиву с PyPI стенд
  запускается без доступа к облаку.
- Из плагина удалён мёртвый код: клиент сервиса зон (`ZoneServiceStub`,
  `ListZonesRequest`) создавался, но не использовался.

## 5. Миграция 1.x → 2.0

1. Заменить в плейбуках, ролях и `group_vars` обращения к меткам как к
   переменным: `role` → `yc_label_role`, `env` → `yc_label_env`,
   `owner_team` → `yc_label_owner_team` и так далее по тому же правилу.
2. Оставить без изменений `ansible_group` (группировка) и `ansible: false`
   (исключение ВМ из inventory).
3. Проверить `ansible_user`/`ansible_port`: они применяются, но теперь ещё и
   дублируются как `yc_label_*` — конфликтов это не создаёт.
4. Прочитать предупреждения плагина после первого запуска: всё, что попало в
   список «не применяется как служебная переменная», нужно либо перенести в
   `yc_label_*`, либо задавать в `group_vars`, а не меткой.

Альтернатива, если переписывать плейбуки не хочется: значения перенести в
`group_vars/` (или `host_vars/` по `yc_name`), а метки оставить только для
группировки и фильтрации.

## 6. Что не исправляется (осознанные ограничения)

- Параметр `cache` у `parse()` принимается для совместимости с интерфейсом
  Ansible, но не используется: inventory каждый раз запрашивается у API. Кэша
  inventory в плагине нет.
- Учитывается только первый сетевой интерфейс ВМ
  (`network_interfaces[0]`); мультиинтерфейсные ВМ получают адрес первого.
- Плагин не фильтрует ВМ по состоянию: остановленная ВМ остаётся в inventory.
- Имя хоста нормализуется: дефисы в имени ВМ заменяются на `_`, поэтому ВМ
  `web-1` адресуется как `web_1` (`ansible web-1` хост не найдёт). Если у ВМ нет
  метки `ansible_user`, подключение идёт от локального пользователя
  контроллера — задавайте `ansible_user` явно.
- Запись `[project.entry-points."ansible.plugins.inventory"]` в `pyproject.toml`
  сохранена для совместимости упаковки upstream, но ansible-core 2.19 entry
  points для inventory-плагинов не читает. Плагин должен лежать в каталоге из
  `inventory_plugins` (`[defaults]` в `ansible.cfg`) или в
  `ANSIBLE_INVENTORY_PLUGINS`.

## 7. Как это проверено

Отдельного облака для проверки не нужно: `tests/fake_yc/` подменяет SDK, а
`tests/run-tests.sh` прогоняет настоящий `ansible-inventory` по десяти сценариям
(инъекция метками, белый список, NIC без IPv4, коллизии имён, пагинация,
`verify_file`, регистр `ansible: false`, аутентификация) и падает с ненулевым
кодом при регрессе.

```bash
./bootstrap.sh        # соберёт локальный .venv
./tests/run-tests.sh  # 11 сценариев, 60 проверок
```
